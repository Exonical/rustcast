# Agent notes

## Layout
- `flux/` Rust workspace (server, capture, encode, input, transport, client). `flux-web/` Go WebTransport (HTTP/3) relay + Next.js viewer (`flux-web/ui`). `drivers/flux-idd/` Rust IddCx driver. `containers/` Rocky 10 GNOME host + relay pod. The host image builds Mesa 25.3.6 RADV/ANV with video codecs enabled (stage `mesa` in containers/host/Containerfile — Rocky strips VK_KHR_video_*) and flux-pod.yaml passes the host's /dev/dri render nodes through as CharDevice volumes. Desktop audio: the host image creates a PipeWire null sink `flux-sink` (rootfs/etc/pipewire/pipewire.conf.d) that flux-server captures and Opus-encodes (feature `audio-pipewire`); it travels as frame-server message type 0x04 and WebTransport uni-stream kind 0x04 to the browser's AudioWorklet player.
- Auth: the relay does OIDC auth-code+PKCE itself (`flux-web/auth.go`, go-oidc; env `FLUX_OIDC_ISSUER/CLIENT_ID/CLIENT_SECRET`, `FLUX_SESSION_SECRET`, admin = member of `FLUX_OIDC_ADMIN_GROUP`, default `flux-admins`). Unset issuer = auth disabled (anonymous admin, loud WARN). WebTransport can't carry cookies, so `/api/webtransport` issues a 60 s single-use `ticket` the browser appends to `/wt`. Host→relay register/heartbeat use a shared bearer `FLUX_RELAY_TOKEN`. The pod runs Authentik (server/worker/postgres/redis on :9000) bootstrapped from `containers/authentik/blueprints/flux.yaml`; secrets are generated once by run.sh into gitignored `containers/.env.authentik` (akadmin password = `AUTHENTIK_BOOTSTRAP_PASSWORD`). Any OIDC provider (e.g. Keycloak) works by changing the issuer/client env.
- Clipboard (text only, 1 MiB cap): host uses Mutter RemoteDesktop `EnableClipboard`/`SelectionRead`/`SetSelection`/`SelectionWrite` (`mime-types` arrives `(as)`-wrapped; the SelectionRead fd is non-blocking). Host→relay frame type 0x05 and relay→host command 0x07 carry `{"mime","data"}` JSON; browser↔relay use control messages `clipboard` / `clipboard-status`. Per-machine policy (`both|off|host_to_client|client_to_host`, default both) and the full-content audit log live in SQLite (`modernc.org/sqlite`, `FLUX_DATA_DIR`, pod PVC `flux-relay-data`; retention `FLUX_AUDIT_RETENTION_DAYS`, default 30). Admin API: `GET/PUT /api/machines/:id/policy`, `GET /api/audit/clipboard[/:id]`; UI at `/audit`.

## Build / test
- Relay: `cd flux-web && go vet ./... && go test ./...` (Go 1.27; the Windows checkout is CRLF, so `gofmt -l` flags every file — check an LF copy instead).
- Rust host build runs inside `containers/host/Containerfile` (features `capture-mutter,encoder-ffmpeg,encoder-vulkan`); Cargo workspace root is `flux/`. Encoder check: `podman exec flux-host su flux -c 'XDG_RUNTIME_DIR=/run/user/1000 journalctl --user -u flux-server | grep "Encoder created"'`.
- Metrics: relay `FLUX_METRICS_ADDR` defaults to `:9101`, host defaults to `127.0.0.1:9102`; metric prefixes are `flux_relay_`, `flux_client_`, and `flux_host_`.
- UI package operations use `npx -y pnpm@12.9.1 ...` (or corepack; `packageManager` is pinned in package.json). Dependency overrides and the `allowBuilds` list live in `flux-web/ui/pnpm-workspace.yaml`.

## Deploy (Windows, Podman machine on WSL2; no Docker)
- Full rebuild + pod replace: `./containers/run.sh` (auto-detects the WSL VM IP for `FLUX_WT_PUBLIC_HOST`; re-run after WSL restarts).
- Relay-only swap keeping the host container: `podman build -f containers/relay/Containerfile -t localhost/flux-relay:latest . && podman rm -f flux-relay && podman run -d --pod flux --name flux-relay -e FLUX_WT_PUBLIC_HOST=<vm-ip> --user flux-web localhost/flux-relay:latest`
- On Windows, install mkcert with `winget install FiloSottile.mkcert`, run `mkcert -install`, then `./containers/run.sh`. The script creates or reuses `containers/certs/relay.pem` and `relay-key.pem`, adds localhost and the advertised VM address as SANs, mounts them read-only, and prints trusted UI URLs at `https://localhost:8443` and (when available) `https://<vm-ip>:8443`. HTTP remains available on port 8080. Without mkcert, the script prints the install hint and preserves HTTP-only behavior.
- The same `FLUX_TLS_CERT` and `FLUX_TLS_KEY` configure WebTransport and the Gin UI/API HTTPS listener; HTTPS defaults to `:8443` and can be disabled with `FLUX_HTTPS_ADDR=off`. The relay still rotates its self-signed WebTransport certificate when neither file is configured.
- For WSL2 localhost UDP forwarding, add `[wsl2]` and `networkingMode=mirrored` to `%UserProfile%\.wslconfig`, then set `FLUX_WT_PUBLIC_HOST=127.0.0.1` before running the script. Without mirrored networking, use the detected VM IP and its trusted certificate URL; Chrome flags are not needed.
- From Git Bash, prefix podman commands that pass absolute container paths with `MSYS_NO_PATHCONV=1`.
- Server log: `MSYS_NO_PATHCONV=1 podman exec flux-host su flux -c 'XDG_RUNTIME_DIR=/run/user/1000 journalctl --user -u flux-server'`; relay: `podman logs flux-relay`.

## Stall / smoothness measurement
- `bash containers/test-stall-source.sh` (looping test clip with player controls in the container's Firefox), then
  `node containers/test-stall.js "machine=default&movePattern=burst&phases=idle:10,mouse:45,idle:10,mouse:45,idle:10" report.json`
  and `bash containers/test-stall-relay.sh default <since-UTC> <until-UTC>` for relay keyframe-recovery counts.
- The server's `Perf: N fps` is a cumulative average since start, not the current rate.

## OS logins (flux-hostd)

- `flux-hostd` (flux/crates/flux-hostd) runs as a system service on the relay-facing port (FLUX_FRAME_PORT, default 8556). It owns registration/machine id (/var/lib/flux/machine-id), PAM-authenticates each relay connection over the wire (frame type 0x06 prompts out, command 0x08 responses in, service `/etc/pam.d/flux`), opens the logind session via pam_open_session, spawns `systemctl --user start flux-session.target` as that user, waits for the agent on 127.0.0.1:8557, and proxies bytes both ways. One session per host: disconnect → "locked"; same user re-login → reattach; other user → busy. `FLUX_SESSION_IDLE_LOGOUT_SECS` (default 0 = never) logs out a locked session.
- `flux-server` runs per-user under `flux-session.target` (user units flux-gnome-session + flux-server, both WantedBy=flux-session.target; pipewire/wireplumber still `systemctl --global enable`). `flux-gen-config` writes bind_address=127.0.0.1, signaling_port=8555 (frame port 8557), frame_quic=false, and no [relay] section (empty base_url already disables registration). The agent reports its encoder via `FLUX_AGENT_STATUS_FILE` ($XDG_RUNTIME_DIR/flux-agent.json), which hostd feeds into registration status (encoder_backend "pending" until then).
- The host image no longer creates the `flux` user or linger. A local test user `devuser` (uid 2101, gid devgroup/8001) is baked in; its password is set at boot by flux-env via `chpasswd` from `FLUX_DEVUSER_PASSWORD` (generated into containers/.env.authentik by run.sh — never in the image).
- PAM/NSS: `/etc/pam.d/flux` tries pam_authentik first, falls back to pam_unix; nsswitch passwd/group/shadow = `files systemd authentik`; pam_mkhomedir + pam_systemd are in the session stack. /home and /var/lib/flux are PVCs (flux-home, flux-machine-id).
- authentik agent (platform 0.72.3, RPMs from https://pkg.goauthentik.io — glibc <= 2.34, fine on Rocky 10): ak-sysd.service is enabled; `flux-ak-join.service` enrolls once (`ak-sysd domains join flux --authentik-url http://localhost:9000` with `AK_SYS_INSECURE_ENV_TOKEN=$FLUX_AK_ENROLLMENT_TOKEN`) when `/etc/authentik/domains/flux.json` is absent. The Agent connector + enrollment token are created by the flux blueprint (authentik_endpoints_connectors_agent.agentconnector / .enrollmenttoken with `key: !Env FLUX_AK_ENROLLMENT_TOKEN`). Enrollment tokens are reusable, so re-enrollment after a pod replace works.
- authentik server bumped to 2026.8.4; redis removed (2026.8 uses postgres for channels/tasks).
- Relay side (`flux-web/login.go`): per-upstream login state machine idle → authenticating → active. The Username prompt is auto-answered with the viewer's OIDC `preferred_username` unless `FLUX_LOGIN_PREFILL=false`; other prompts go to the viewer as `login` control messages and come back as `login-response`. Only the same OIDC subject may join an active session; last viewer leaving, `{"type":"lock"}` (toolbar 🔒 / Ctrl+Alt+Shift+L) or admin disconnect sends command 0x09 (lock). Every login result is recorded in SQLite `host_logins` (`GET /api/audit/logins`), sessions carry `os_user`, and clipboard audit rows get `os_user`.
- `pam_authentik` interactive login is an authentik **Enterprise** feature; without a license the host logs `interactive authentication is not licensed for this domain` and only local (pam_unix) users such as devuser can log in. NSS resolution of authentik users works without a license.
